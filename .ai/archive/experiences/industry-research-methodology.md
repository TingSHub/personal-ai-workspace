## 一、方法论精华（跨技能吸收项）

### 1. 三高打分 + 两步走审计留痕（industry-analysis）
- 裸打分 → 独立审计 → 改分留痕（如 `5→4` 标注前瞻理由），防自我印证
- 财务校验"校验状态"与"趋势备注"分列——避免把"毛利下滑"等趋势误标成"偏乐观"
- 偏乐观必须写明前瞻理由，否则下修到数据区间
- **实测证据**：内存互连增长 5→4（当前营收 +26.6% 未达 30% 门槛）、交换机利润 4→3（锐捷净利率 3.5%、新华三 ICT 毛利 16.5% 被服务器摊薄）

### 2. 防编造硬约束（industry-analysis）
- 估值分位优先用脚本取真实数据；脚本不可用则降级定性区间（高/中/低），**禁止凭空给出具体数值**
- 推算 PE/PEG 必须注明分子分母口径与来源机构
- **实测证据**：tushare 接入前全程无编造数字；接入后 PEG 一律 ❓ 降级、澜起 PE 489x 口径异常如实标注不修饰

### 3. Bear Case 卡片（反共识对冲，industry-analysis）
- 每份报告独立产出空头视角：主线最可能错在哪、空头最强三条论据、什么数据出现即证伪（量化证伪信号，如"capex 环比转负、旭创毛利连两季 <40%"）

### 4. 尽调清单 + 数据置信度总评（industry-analysis）
- 报告头部标"X 项联网核验 / Y 项定性判断 / Z 项缺失"，让用户一眼知道能信几分（实测：32 核验/12 定性/5 待补全）
- 末尾列：①低置信数字（需一手核实）②翻盘假设 ③建议追问的 3-5 个问题——最低幻觉风险、最高实操价值的输出

### 5. 证据账本 + 证据就绪门槛（industry-cycle-analysis）
- 每条关键声明记台账：发布方/日期/访问日期/期间/地域/定义/定位（locator）/**opened 分层**——只有实际打开原始来源的才升级为"事实"，搜索摘要/转述停留 Tier-3 如实标注（实测 23 条台账 E1-E23）
- 五车道就绪门槛（产业链 2/需求 3/供给 3/价格-订单-库存-利润 3/资本市场 2 个 opened 来源）达标后才可命名周期阶段；缺口则结论标"暂定"
- 周期阶段判断与结论状态/置信度/上调下调条件**分离为独立字段**（"扩张"可与"暂定"并存）
- **时间同步与披露状态分层**：先查系统时间，区分整期实际/部分月度实际/指引/预测，禁止写"最新已披露期"

### 6. 报告校验脚本契约（industry-cycle-analysis）
- `validate_report.py --mode full --strict`（纯标准库）把反样板/防填充规则变成可执行检查——实测第 1 轮抓到 7 个真实缺陷（生产控制方式未写明、上市地标签不合规、标题误触发校验），修复后 0 错误 0 警告
- 校验偏结构导向，实质质量仍依赖作者自律——校验通过 ≠ 内容可信，需配合质量清单实质审查

### 7. 流水线编排价值（investagent）
- Serenity 式"先排稀缺层再排公司"（Token 经济→带宽/散热约束→稀缺层→公司池）避免直接列热门股的通病；跨模块数据同源保证自洽（筛选池→辩论→回测结论互不冲突）
- **实测证据（环境跑通后）**：稀缺层排序（交换芯片>800G 智算交换机>液冷>光模块>服务器整机）与 UZI 评审、TradingAgents 辩论三方共振；DCF 297.5 亿 vs 市值 1,069 亿 vs 券商 PE 20-28x 的冲突被完整呈现而非抹平

### 8. TAM/SAM/SOM 测算 + 发展阶段量化阈值（dazhiruoyu）
- 市场规模三层拆解：TAM（总潜在）→ SAM（可服务）→ SOM（可获得，分视角：在位者/新进入者）
- 阶段判断阈值：增速>30% 成长期、CR3>50% 寡头、连续 2 年负增长衰退
- ⚠️ **阈值偏 C 端**：B 端使用需修正（如"资金<1000 万为低壁垒"与 ICT 行业数十亿研发脱节；用户画像需改造成"行业×采购特征"）

### 9. 来源/推测标注规范（dazhiruoyu、industry-report-generator）
- 推测内容标"基于公开信息推测"；数据缺失明确说明不编造
- 来源注脚 + 附录来源清单 + 口径差异说明（多机构数据并列标注）

## 二、六技能完整档案（AI 投研工作流接入参考）

### 1. industry-analysis（GitHub，产业链+投资分析）——通用首选

**定位**：输入行业/主题/公司 → 6 阶段结构化研究（范围回显→产业链图谱→三高打分→赛道下钻→标的梳理→估值赔率+Bear Case）→ 自包含 HTML 可视化报告。A 股视角。

**✅ 优点（实测验证）**
- 6 阶段全流程，阶段 0 先回显行业边界再开干（含必判项"核心环节是否在境外"，避免漏掉海外利润池）
- 三高打分 + 两步走审计留痕（防自我印证）+ 财务交叉校验（状态/趋势分列）
- 防编造硬约束全程生效：估值分位脚本优先、禁止凭空数值、PEG 失真标记
- Bear Case 反共识 + 尽调清单 + 置信度总评——最低幻觉风险的输出设计
- 自包含 HTML（内联 CSS/SVG：产业链图谱/热力矩阵/雷达图/四象限），离线可打开可截图
- **tushare 估值接入后**（`industry-analysis/scripts/fetch_valuation_tushare.py`）：5 标的一次跑通、3Y/5Y 复跑可重复、CLI 与原版兼容——估值从"印象"变成"可验证"：
  - 改变实质判断：识别出紫光国微（002049）唯一低分位核心标的（PE 32%/PB 8%）+ Q1 净利 +180%——"高价值+低估值"组合，定性判断做不到
  - 暴露数据质量问题：澜起 PE 489x 口径异常（如实标注待核验）、星网锐捷 PE 99% 分位 vs 盈利拐点致静态分位失真
  - 交叉印证可靠：000938 PE 50.3 与第三方口径（PE≈50）吻合

**❌ 缺点（实测发现）**
- 静态 SVG 图谱维护成本高（数据更新需手改坐标）
- 多源口径冲突缺裁决机制（浪潮份额 28%–52% 并存，只能并列标注）
- 无交互场景"回显确认"只能单方面回显（应标注"未确认"状态）
- 深度模式写作量约普通报告 3 倍
- 估值脚本依赖 pandas（项目 .venv 已装）；上游原版用 akshare（本项目用 tushare 版替代，不改上游）

**适用场景**：通用行业分析首选（投研/尽调/产业链梳理）；与其他 skill 组合：财务数据接 tushare-connector、搜索接 multi-search

### 2. industry-cycle-analysis（GitHub，供需周期诊断）——深度研究档

**定位**：从真实经济出发（真实需求→预算/订单→有效供给→价格/库存/利润→资本开支→周期转折→市场预期阶段）判断行业周期阶段与市场预期差。核心信条："先理解真实世界，再解释市场预期"。

**✅ 优点（实测验证）**
- **证据纪律全场最强**：搜索结果与已打开原始来源强制分层（opened=是 才有 URL+locator）、23 条证据台账、五车道就绪门槛、声明可追溯到 E# 编号
- **校验脚本契约**：`validate_report.py --mode full --strict`（纯标准库零依赖）实测抓出 7 个真实缺陷（生产控制方式/上市地标签/标题误触发），把反样板规则变成可执行检查
- 周期判断与结论状态/置信度分离（"扩张"可与"暂定"并存）、时间同步+披露状态分层（禁止"最新已披露期"）
- 隐含预期反推（25x 退出需 2028E 归母 51.8 亿，支持度"偏紧"）、分层代理篮子（ETF/子链/代表公司三层）、政策重要性闸门
- 反油腔规则：禁重复句式、禁循环定义、禁把模板填空当结论
- 双读者结构：正文 0-10 节自足（新手可读懂）+ 附录 A/B/C 审计材料（老手可核验）

**❌ 缺点（实测发现）**
- 写作成本最高：23 条台账 + 9 进阶视角 + 6 节点×6 字段 ≈ 普通报告 3 倍——适合深度研究，不适合快速扫描
- 校验偏结构导向：对无真实证据的填充式写作只能部分拦截，实质质量靠作者自律
- JS 渲染行情页（中证指数官网/财联社）抓取失败需回退聚合源（如实记 opened=否）
- 中文来源多为媒体转述（Tier-3），原始 PDF（采购公示/公司公告）难以直接打开

**适用场景**：周期判断、资本周期定位、风口是否晚周期、深度行业研究；与 industry-analysis 互补（后者管"产业链+标的"，本技能管"供需周期+预期差"）

### 3. investagent（GitHub，全流程编排）——环境齐备时最强

**定位**：六阶段流水线（主题→Serenity 产业链扫描→Buffett 价值筛选→UZI 个股深度→TradingAgents 多空辩论→QuantDinger 量化回测），覆盖 A股/港股/美股。5 大子模块 skill 编排。

**✅ 优点（实测验证——环境打通后）**
- **流水线编排价值**：Serenity"先排稀缺层再排公司"（Token 经济→带宽/散热约束→稀缺层→公司池）避免直接列热门股；稀缺层排序（交换芯片>800G 智算交换机>液冷>光模块>服务器整机）与下游模块结论自洽
- **数据真实性质变**：20 股 PE/ROE/毛利率/负债率、紫光 26 个月日线、865 项投资者评审全部实拉（baostock/akshare），筛选/估值/回测/辩论输入全部锚定真实数据
- **TradingAgents 真实 LLM 辩论**（DeepSeek，7 次真实 API）：看空方产出"剔除一次性收益后实际 PE 58 倍以上""CSP capex 不及 +90% 则戴维斯双杀"等独立交叉验证论点；交易员裁决"观望+回踩 35-36 轻仓+33.5 止损"——与人工分析形成独立校验
- **QuantDinger Docker 部署跑通 + 真实回测**：postgres/redis/backend 构建 + up + health ✓ + 回测任务真实入队执行
- **跨模块冲突如实呈现**：UZI DCF 297.5 亿 vs 市值 1,069 亿 vs 券商 PE 20-28x——DCF 与 Comps 相反结论完整保留，未抹平
- 降级不伪装：环境不足时用真实数据+等效脚本产出可复现结果

**❌ 缺点（实测发现）**
- **依赖成本全场最高**：项目 .venv（akshare/yfinance/baostock/ddgs/playwright）+ 外部 LLM key（DEEPSEEK_API_KEY）+ Docker（sg docker 方式）
- UZI HTML 渲染需 playwright chromium（184MB 下载，国内网络超时）——数据完整但报告渲染受限
- TradingAgents 宏观节点需 FRED_API_KEY（免费注册项，未配则中断）
- QuantDinger frontend 有 compose v1 嵌套变量兼容问题（backend 可用，frontend 非必需）
- akshare 东财接口偶发断连（用 baostock/腾讯 fallback）；Tushare daily 返回倒序（回测需反转）

**适用场景**：环境齐备时的全流程深度投研（单个行业/主题/个股）；量化验证投研主线（回测结论直接支撑报告）

### 4. dazhiruoyu（SkillHub，市场调研量化）——商业决策场景

**✅**：42 框架覆盖 38 行业 + 宏观/策略/固收/金融工程，领先/验证/反转指标结构清晰，券商风格证据链
**❌**：框架库有行业盲区（无 ICT 设备类，实测路由选 AI 框架+自行补充）；部分文件为 PDF 提取碎片（bullet 残留/重复行/乱序表格）质量参差需抽检；无固定交付模板；数据口径冲突无裁决

### 6. industry-report-generator（SkillHub，报告骨架）——Word 兜底

**✅**：八步框架保底全面（执行摘要/PESTEL/供需/趋势/建议/风险），来源标注规范（正文注脚+附录清单+口径说明，实测 8 注脚+附录）；与 docx skill 协作顺畅；格式规范详细（黑体/宋体字号页边距）
**❌**：框架最薄（PESTEL 固定顺序弱化行业第一驱动——ICT 的 T 维技术才是主轴）；无防幻觉机制（深度依赖 Agent）；docx npm 沙箱安装位置异常 + Heading 缺 outlineLvl（Word TOC 失效需显式 paragraphStyles）；无 soffice/pandoc 渲染验证工具链
**适用**：需要正式 Word 交付物的场景兜底；八步骨架可作报告结构参考

## 三、通用教训

1. **全部技能强依赖 WebSearch**，无内置数据源接入；机构口径冲突普遍（浪潮份额 28%–52% 并存）无裁决机制——关键数字需交叉验证到一手财报
2. **多模块编排依赖成本**（investagent）：环境三件套（venv 依赖/外部 LLM key/Docker）是前置评估项——实测打通前真实执行率 40%，打通后 90%；选型时先评估环境可得性
3. **周期分析写作成本高**（industry-cycle-analysis）：适合深度研究，不适合快速扫描——按任务档位选型
4. **行情/实时数据抓取难**：行情页多为 JS 渲染，WebFetch 拿不到——记为失败尝试并回退聚合源
5. **框架库类技能有行业盲区**（ai-market-analysis）：路由需人工判断最近框架（AI 框架>机械框架，理由：增长引擎决定分析主轴）+ 自行补充行业知识
6. **环境依赖坑清单**：pip PEP 668（用项目 .venv 解决，勿 --break-system-packages 污染系统）；`python` vs `python3`；reportlab 中文字体静默回退 Helvetica（只警告不报错）；docx npm 沙箱 + outlineLvl；playwright chromium 184MB 下载超时（国内网络）；akshare 东财断连（baostock/腾讯 fallback）；Tushare daily 倒序（回测需反转）
7. **固定模板的局限**（industry-report-generator）：模板只做保底，行业纵深靠 Agent 补——按行业主轴重排模板优先级
8. **无交互场景局限**（industry-analysis）："先回显确认"只能单方面回显，应标注"未确认"状态
9. **数据源口径差异**（TAM 场景）：同一市场多机构差异大（AI 服务器 2,530 亿 vs 259 亿美元）——双口径并列+注明来源，不强行归一
