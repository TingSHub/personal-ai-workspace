# MVP 评估报告：investagent 研究报告 → 投资者阅读 HTML

- **验证案例**：贵州茅台（600519）· 输入 `investagent-600519-20260815.md`（306 行 / 31.7KB）
- **执行日期**：2026-08-16
- **执行链路**：研究报告（原样保留）→ html-ppt-skill 设计体系 → 单文件 HTML（内联 SVG 图表，无 CDN 依赖，本地可打开）
- **产物**：`outputs/maotai-600519/investment-report.html`（约 9,300px 高 / 7 张 SVG 图表 / 40+ 卡片）· `outputs/maotai-600519/preview.png`（全页截图）

---

## 结论先行

**最小闭环成立。** 一次转换（无 Agent 编排、无中间层）即可把 investagent 研究报告变成结构完整、图表化、可读的投资者页面。页面质量的关键变量不是「更聪明的 Agent」，而是**内容取舍判断 + 数据到图表的映射**——这两件事在 MVP 中由人工完成，是后续引入 Agent 的候选点。

## 1. 普通投资者是否愿意阅读？

**倾向：愿意（有条件）。** 判断依据（来自转换过程中的实际取舍）：

| 促进阅读的设计 | 转换证据 |
|---|---|
| 一屏一个核心观点 | 每个部分开头一句「结论横幅」（如「2025 年首次双降——增长引擎第一次减速，这是核心矛盾」），读者 2 秒抓住部分主旨，再决定是否深入 |
| 核心矛盾前置 | Hero 区 6 个关键统计（市值/PE/股息率/毛利/净利/ROE）+ 一句「当前处于增长验证阶段」结论，报告气质一眼可见 |
| 无 AI 痕迹 | 转换时删除了研究框架名（Buffett/UZI/TradingAgents/QuantDinger）、模块执行状态、降级说明、失败重试记录、数据快照说明等全部 AI 内部字段——页面呈现的是「一份完整的投资观点」，而非「一个 AI 跑完的日志」 |
| 有行动指引 | 结尾「7 项季度检查清单 + 3 个信号」给了投资者明确下一步：盯什么、什么算证伪、什么算复苏 |

**保留条件**：(a) 衬线编辑风是审美选择，部分读者可能偏好更现代的界面；(b) 页面总长仍约 9300px，长文滚动对部分读者是负担（顶栏锚点导航缓解）；(c) 阅读意愿本质取决于内容质量——本次输入报告本身证据充分、结论明确，HTML 只是降低了阅读成本，没有制造阅读意愿。

## 2. 是否比原始 Markdown 更容易理解？

**大部分内容：是。** 转换把 Markdown 的「表格 + 长段落 + 分层标题」重组为「一句话结论 + 图表 + 卡片」：

| 原始 Markdown | HTML 页面 | 理解成本变化 |
|---|---|---|
| 财务快照表（6 年 × 9 指标混排） | 拆成 4 张卡片：营收净利趋势图 / 利润率 ROE 线图 / 现金流转换率图 / 资产负债表 | 「2025 双降」从表格角落里的一行，变成图表上两处标红的负增长标签——**核心矛盾 2 秒可见** |
| 价格体系文字描述（1169→1269→1369…） | 价格阶梯图：出厂价/i 茅台/自营店/批价同轴对比 | 「批价距新指导价仅 21 元」的紧张感可感知，而非需要心算 |
| 估值分歧（DCF 1120–1174 / 现价 1342 / 目标 1693 / 四派系价位） | 估值地图（单轴定位图） | 「历史便宜、绝对不便宜」的中间态一目了然 |
| 多空辩论（两段长引文） | 左右对比卡（5 条 vs 5 条，▲▼ 符号） | 对抗结构可见，立场可快速扫读 |
| 回测结论（4 行参数表） | 水平条形图 + 一句结论 | 「只有极端便宜才赚钱」可视化 |
| 八问筛选表（含数据依据列） | 8 个结论 chips（6✓ 2⚠） | 快，但证据列被压缩 |

**不升反降的部分（诚实记录）**：八问筛选表的「数据依据」列对进阶读者有价值，压缩成 chips 丢失了论证细节；PE 口径差异（tushare 20.28 vs UZI 18.84）这类「AI 内部审计信息」被删掉，但部分严谨投资者可能想知道数据来源分歧。整体净效果：**可读性显著提升，论证厚度略降**——对「普通投资者」这一目标人群是正确的取舍。

## 3. 哪些内容最有价值？

按「投资者感知价值」排序（转换过程观察）：

1. **价格体系阶梯图** —— 一次提价逻辑 + 批价倒挂风险，是整个报告压缩度最高的一张图
2. **估值地图** —— 把「分歧点在于增长假设」翻译成空间位置，机构目标价与保守 DCF 的落差成为可感知的距离
3. **营收/净利双柱图** —— 6 年增长的「减速瞬间」具象化，报告的研究问题（增长可持续性）自身可视化
4. **多空对比卡** —— 结构变量 vs 周期变量的对抗，比任何单一结论都更有信息量
5. **7 项检查清单 + 3 信号** —— 报告从「读完就完」变成「有后续动作」，这是 Markdown 原报告没有强化的价值
6. **现金流转换率图（107% → 74.7% → 158.8% + 90% 健康线）** —— 「裂缝」与「回升」两个信号并置，空方核心论据可视化

## 4. 哪些地方需要后续引入 Agent 优化？

**瓶颈不在「判断」，在「执行」。** 本次转换耗时最多、最易出错的是手工环节：

| 优先级 | Agent 化方向 | 现状痛点 | 预期收益 |
|---|---|---|---|
| P0 | **数据 → 图表映射 Agent** | 7 张图全部手工算坐标（如 `y = 265 - v/1800*225`），约 60+ 数值手工转录，慢且易错 | 一次转换从「小时级」降到「分钟级」；图表可参数化复用 |
| P0 | **数值一致性校验 Agent** | 页面数字与源报告数字无自动核对（本次靠人工回读） | 消灭转录错误，投资者报告的数字可信度是底线 |
| P1 | **内容压缩 Agent** | 「每节一句核心观点 + 精选卡片」的取舍依赖判断力，MVP 靠人完成 | 报告体量规模化（周报/多公司）时唯一可行路径 |
| P1 | **版式模板化** | 每次设计成本高；本次借鉴了 html-ppt-skill 的 token 体系但没有固定版式 | 固定「投资者报告」版式模板，Agent 只填内容不碰设计 |
| P2 | **增量更新 Agent** | 报告重跑后整页重写 | 只重算变化的图表/数字，适合季报跟踪场景 |

**明确不需要 Agent 化的**：研究环节（input 已经完整）、内容扩展（页面定位是忠实呈现，不是新增判断）、运行时（单文件静态页零服务）。「Researcher → Visual Director」式编排在这个场景验证下来是过度的——**最短链路（报告 → 模板 → 图表 Agent）就够**。

## 过程观察（给 Experience 的候选结论）

1. **html-ppt-skill 可复用其设计 token 体系**（CSS 变量、主题文件结构），但其运行时（翻页、presenter、FX）对长文报告是负资产——定制时只取设计层，不要 runtime。
2. **红涨绿跌**是 A 股设计红线，AI 默认配色的蓝涨绿跌会直接误导中国投资者——任何财务页面都要显式声明涨跌色。
3. **「删除 AI 痕迹」是增值动作而非损失**：删除的框架名/执行状态约占总内容 15%，删除后报告更可信而非更单薄。
4. 单文件 + 系统字体 + 无 CDN = 本地可开、可邮件、可归档，这个技术约束不应放松。
