# Reference Podcast Distill: reusable rules

来源：`outputs/companies/紫光股份/2026-08-21/distill/visual-frames/` 全组截图、`visual-style.md`、`debate-rounds` 与参考转写。

## 1. 开场信息架构

参考节目不是主持人自我介绍开场，而是：

```text
客观数据冲突/市场变化钩子
→ 2–4 个开场数据卡
→ 本期目录/话题总览
→ 主持人身份与观察角度
→ 第一个话题
```

自我介绍是角色定位层，不是第一句台词；它应在冷开场后出现。

## 2. 内容层与字幕层分工

- 内容区：回答“这句话为什么重要”，放数据卡、对比条、路线图、证据列表和结论结构。
- 字幕区：只显示当前真实音频 turn，不重复内容区的完整台词。
- 说话人胶囊：只表达当前 speaker 和角色，不承担完整对白。
- 同一句话最多有一个完整文本载体；其它区域只保留压缩后的证据锚点。

## 3. 开场客观数据卡

开场可以从以下数据组合中选择 2–4 项：

- 股价阶段性涨跌幅或区间变化；
- PE/PB/股息率或历史估值分位；
- 营收、利润、毛利率、现金流；
- 业务规模、市场份额或重要公告变化。

这些是客观背景数据，不等于买卖建议。估值数据可以进入开场和话题证据，但不是研究或脚本通过的硬门槛；硬门槛是来源、期间、口径和是否存在投资建议化表达。

## 4. 目录与进度

- 开场要有本期话题总览，让观众知道后面会讲什么。
- 底部导航显示真实话题标题，不显示内部 `topic_id`。
- 当前话题必须高亮。
- 进度条必须由真实音频总时长驱动，连续从 0 到 100%，不能只是静态数字序列。
- 导航、进度和内容 Scene 必须共享同一 manifest 时间轴。

## 5. 话题页的可复用语法

每个话题页保持：

- 话题编号 + 提问式标题；
- 1–3 个彩色细线数据区块；
- 大数字、对比条、列表或路线图至少一种证据表达；
- 当前 speaker 胶囊；
- 底部实时字幕；
- 当前话题导航状态。

页面不应把逐句对话稿完整铺在内容区。内容页讲证据，字幕讲当前说话内容。

## 6. 主持人角色与音色

- 风险/价值方：提出最强质疑、指出利润和资产负债表风险。
- 数据/趋势方：承认合理部分，再用结构、趋势和新证据反击。
- 两个角色可以互换性别，但角色方法不能漂移。
- 账号默认：顾慎言=风险与反证方，林知微=数据与趋势方；每句话独立合成，严格交替。

## 7. 复用判定

以下内容属于节目级资产，可跨公司复用：固定层、目录结构、进度条、主持人角色、回合语法、数据卡组件、字幕位置和颜色语义。

以下内容属于公司级输入：公司名、股价/估值背景、话题标题、数字、证据、图表数据、当前事件和音频文本。
